## 检索到的相关在先技术

### 高相关度（需要重点区分）

#### 1. US 20040006403A1 - Automated validation processing and workflow management

- **内容**：自动化验证处理和工作流管理系统，在计算环境中执行自动化验证并管理对应工作流。
- **与本发明的区别**：
  - 该专利面向通用数据验证和工作流管理，不涉及 AI Agent 行为约束
  - 不包含分层约束模型（六层）
  - 不包含测试工具选型、证据归因、判断基线等测试工程特有概念
  - 不涉及 AI Agent 的不确定性管理
  - 申请时间为 2003 年，远早于大语言模型 Agent 时代

#### 2. US 20210382816 - Requirements to Test System and Method

- **内容**：从需求自动生成 UI 测试脚本并执行，将可视化工作流转换为机器可消费的格式。
- **与本发明的区别**：
  - 该专利关注"需求到测试脚本的自动生成"，本发明关注"约束 AI Agent 的测试工程行为"
  - 不包含流程门禁校验机制
  - 不包含中断恢复和状态持久化
  - 不涉及 Agent 行为的不确定性约束
  - 不包含判断基线层和三分法

#### 3. US 20220091966 - Systems and Methods for Facilitating Software Validation Within a Production Environment

- **内容**：在生产环境中进行软件验证的系统和方法。
- **与本发明的区别**：
  - 面向生产环境验证，不是测试工程闭环
  - 不涉及 AI Agent 行为约束
  - 不包含分层约束模型

#### 4. US 20240078167 - Remote Validation for Regulated Environments

- **内容**：使用自动化 agent 在本地系统上监督受监管应用的验证过程。
- **与本发明的区别**：
  - 面向受监管环境的合规验证，不是功能测试工程
  - 其 "agent" 是传统自动化代理，不是大语言模型 Agent
  - 不包含六层约束模型、工具选型、证据归因等概念

## 新颖性评估结论

### 本发明的核心新颖点

经过检索分析，本发明的以下技术特征组合在现有技术中**未发现高度相似的在先申请**：

1. **六层分层约束模型应用于 AI Agent 测试工程**：现有技术中，质量门/验证门主要用于 CI/CD 发布流程或代码开发流程，没有发现将分层约束模型专门应用于约束 AI Agent 功能测试行为的在先技术。

2. **测试实施步骤的结构化门禁校验**：现有的 Agent 工作流验证主要是代码层面的（lint、type check、unit test），没有发现对测试实施产物（环境前置文档、工具选型表、执行记录）进行 Markdown 结构校验和内容非空校验的在先技术。

3. **测试工具选型作为强制门禁步骤**：现有技术中，工具选型通常是隐含在测试执行中的，没有发现将其作为独立的、有校验规则的强制步骤的在先技术。

4. **三分法判断基线 + 业务字典**：现有技术中的质量门通常是二值判断（pass/fail），没有发现将测试产出按"正常/异常/未知"三分法分类、且基于业务字典做判定的在先技术。

5. **目标产物模式的动态步骤裁剪**：现有工作流系统通常是固定步骤，没有发现根据目标产物类型动态确定必经步骤集合的在先技术。

### 潜在风险点

1. **"工作流 + 门禁"的通用概念**已有大量在先技术（US 20040006403A1 等）。本发明需要强调的是"面向 AI Agent 测试工程"的特定应用和六层模型的创新组合，而不是通用的工作流门禁概念。

2. **"Agent + 质量门"的组合**在 2025-2026 年开始出现（arxiv 2603.15676、yess.ai 等），但这些都面向代码开发或 LLM 发布，不是测试工程。需要在权利要求中明确限定"测试工程"场景。

3. **中断恢复和状态持久化**是通用技术特征，单独不具备新颖性。但与六层约束模型和测试门禁结合后，作为从属权利要求是合理的。

### 建议

1. **权利要求的核心保护点应聚焦在**：六层约束模型 + 流程门禁 + 测试工程场景的特定组合。这个组合在现有技术中未发现高度相似的在先申请。

2. **独立权利要求不宜过于上位**：如果只写"一种基于门禁的 AI Agent 工作流方法"，容易被 US 20040006403A1 等在先技术影响新颖性。必须限定"测试工程闭环"和"六层约束"。

3. **建议在正式提交前**，在 CNIPA 专利检索系统（https://pss-system.cponline.cnipa.gov.cn/）做一次精确检索，使用以下 IPC 分类号组合：
   - G06F 11/36（软件测试）
   - G06N 20/00（机器学习）
   - G06F 8/20（软件工程）

4. **当前评估**：基于公开渠道检索，本发明的核心技术方案具备新颖性和创造性的基础。六层约束模型 + 流程门禁系统 + 测试工程特定场景的组合，在现有技术中未发现实质性相同的在先申请。
