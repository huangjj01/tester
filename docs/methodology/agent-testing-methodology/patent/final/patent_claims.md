# 权利要求书

## 独立权利要求 1（方法权利要求）

1. 一种用于 AI Agent 测试实施流程的配置化门禁控制方法，由计算设备执行，其特征在于，包括以下步骤：

S1、配置加载步骤：读取声明式工作流配置数据，所述工作流配置数据定义了有序的步骤序列、每个步骤的产物输出路径、步骤间的依赖关系和每个步骤的门禁校验规则；

S2、实例创建步骤：根据接收到的任务标识和目标产物类型，创建工作流运行实例，生成包含时间戳的唯一运行标识，在本地存储中建立运行状态数据和步骤状态数据，并根据所述目标产物类型确定必经步骤集合，将非必经步骤标记为当前目标不要求状态；

S3、步骤推进步骤：根据所述步骤间的依赖关系和各步骤的当前状态，确定当前应执行的步骤，并向 AI Agent 输出当前步骤的产物输出路径和门禁校验要求；

S4、门禁校验步骤：当 AI Agent 完成当前步骤的产物生成后，对所述产物执行门禁校验，所述门禁校验包括：
- S4a、依赖校验：检查当前步骤的所有前置依赖步骤是否均处于已完成状态，任一依赖步骤未完成时拒绝执行后续校验；
- S4b、产物存在性校验：检查当前步骤配置的产物输出路径对应的文件是否存在；
- S4c、产物内容校验：根据当前步骤配置的门禁校验规则，对产物文件内容执行结构校验和有效性校验；

S5、状态更新步骤：
- 当所述门禁校验通过时，将当前步骤的状态更新为已完成，记录完成时间，并根据依赖关系将运行实例的当前步骤指针推进至下一个处于等待执行状态的步骤；
- 当所述门禁校验未通过时，将当前步骤的状态更新为已阻塞，将校验错误信息写入步骤状态数据，阻止当前步骤指针推进；

S6、状态持久化步骤：在每次状态变更后，将运行状态数据和步骤状态数据持久化至本地存储，使得当 AI Agent 执行中断后，能够通过读取所述持久化数据恢复执行进度，而不依赖 AI Agent 的对话上下文。

## 从属权利要求 2-8（门禁技术细化）

2. 根据权利要求 1 所述的方法，其特征在于，所述步骤 S4c 中的结构校验包括标题校验，所述标题校验的具体步骤为：
- 解析产物文件中的标题标记，提取所有标题的位置和文本；
- 对门禁校验规则中要求的每个必需标题，检查产物文件中是否存在文本精确匹配的标题；
- 对每个匹配到的标题，确定其正文范围为当前标题位置到下一个标题位置之间的内容区域，检查所述正文范围内是否存在至少一行非空白内容；
- 缺失标题或标题下无非空白内容时，生成对应的校验错误信息。

3. 根据权利要求 1 所述的方法，其特征在于，所述步骤 S4c 中的有效性校验包括表格有效数据校验，所述表格有效数据校验的具体步骤为：
- 解析产物文件中的表格结构，提取表头列名和数据行；
- 检查表头是否包含门禁校验规则中要求的所有必需列；
- 对数据行中每个单元格的值执行占位符判定，所述占位符判定规则包括：空值、尖括号包围的模板文本、不区分大小写的待定标记和预定义的待补充标记；
- 当所有数据行的关键列均被判定为占位符时，生成校验失败信息。

4. 根据权利要求 1 所述的方法，其特征在于，所述步骤 S2 中，根据目标产物类型确定必经步骤集合的具体方式为：从所述工作流配置数据中读取目标产物类型到终点步骤的映射关系，将步骤序列中从首个步骤到所述终点步骤之间的所有步骤标记为必经步骤，将终点步骤之后的步骤标记为当前目标不要求状态。

5. 根据权利要求 1 所述的方法，其特征在于，所述步骤 S4 还具有幂等性：当对已处于已完成状态的步骤重复执行门禁校验时，直接返回成功结果，不修改已记录的完成时间，不重复推进当前步骤指针。

6. 根据权利要求 1 所述的方法，其特征在于，所述步骤 S1 还包括配置合法性校验：
- 校验步骤序列中所有步骤标识的唯一性，存在重复标识时拒绝加载配置；
- 校验每个步骤声明的依赖步骤标识在步骤序列中存在；
- 校验目标产物映射中的终点步骤标识在步骤序列中存在。

7. 根据权利要求 1 所述的方法，其特征在于，所述步骤 S6 中的中断恢复具体包括：
- AI Agent 执行中断后，通过状态查询接口读取持久化的运行状态数据，获取当前运行状态和各步骤状态；
- 通过下一步查询接口获取当前应执行步骤的产物路径和门禁校验要求；
- 若当前步骤的产物文件已存在但步骤状态未完成，AI Agent 在已有产物内容基础上补全，而非覆盖；
- 补全后仍须通过门禁校验步骤，不得直接标记为已完成。

8. 根据权利要求 1 所述的方法，其特征在于，还包括产物合并步骤：按步骤序列顺序，将所有处于已完成状态的步骤的产物文件内容合并输出为完整的测试交付文档。

## 从属权利要求 9-12（测试实施场景特征）

9. 根据权利要求 1 所述的方法，其特征在于，所述工作流配置数据定义的步骤序列包括以下测试实施步骤：输入资料确认步骤、测试范围确认步骤、环境前置判断步骤、测试工具选型步骤、测试实施指南步骤、测试执行记录步骤、最终报告步骤和测试工程反思步骤；所述步骤之间按顺序建立依赖关系。

10. 根据权利要求 9 所述的方法，其特征在于，所述测试工具选型步骤的门禁校验规则为表格有效数据校验，要求产物中包含具有用例场景、工具覆盖情况、选用工具、新增需求、断言方式、选择理由和缺口风险列的表格，且至少一行数据的关键列为非占位符有效数据。

11. 根据权利要求 9 所述的方法，其特征在于，所述环境前置判断步骤的门禁校验规则为标题校验，要求产物中包含目标环境、版本信息、服务配置、启动参数、外部依赖和恢复基线标题，且每个标题下存在非空白正文内容。

12. 根据权利要求 1 所述的方法，其特征在于，还包括判断基线约束步骤：基于预定义的业务行为字典和已知缺陷库，将 AI Agent 的测试产出按三分法分类为正常、异常和未知三类；其中正常类要求命中业务字典且跨层证据自洽，异常类要求命中异常模式或跨层证据不自洽，未知类标记为待确认且禁止写入正式结论。

## 独立权利要求 13（系统权利要求）

13. 一种用于 AI Agent 测试实施流程的配置化门禁控制系统，其特征在于，包括：

工作流配置模块，用于加载和解析声明式工作流配置数据，所述工作流配置数据定义步骤序列、步骤间依赖关系、每个步骤的产物输出路径和门禁校验规则；所述工作流配置模块还用于在加载时执行配置合法性校验，包括步骤标识唯一性校验、依赖步骤存在性校验和目标终点步骤存在性校验，配置不合法时拒绝创建运行实例；

状态管理模块，用于创建工作流运行实例，生成包含时间戳的唯一运行标识，维护运行状态数据和步骤状态数据并将其持久化至本地存储；所述运行状态数据包括运行标识、目标产物类型、当前步骤指针和运行状态；所述步骤状态数据包括每个步骤的当前状态、完成时间和校验错误列表；所述步骤状态包括等待执行、已阻塞、已完成和当前目标不要求；

目标产物模式模块，用于根据用户指定的目标产物类型，从工作流配置数据中确定终点步骤，将步骤序列中首个步骤到终点步骤之间的步骤标记为必经步骤，将终点步骤之后的步骤标记为当前目标不要求状态；

门禁校验模块，用于在 AI Agent 声明步骤完成时，依次执行依赖校验、产物存在性校验和产物内容校验；所述产物内容校验包括：
- 标题存在性校验：检查产物文件中是否存在配置要求的标题文本；
- 标题内容非空校验：检查每个必需标题下方是否存在非空白正文内容；
- 表格列完整性校验：检查产物文件中的表格表头是否包含所有必需列；
- 有效数据校验：检查表格数据行中是否存在至少一行非占位符的有效数据；
校验通过时通知状态管理模块将步骤状态更新为已完成并推进当前步骤指针，校验未通过时通知状态管理模块将步骤状态更新为已阻塞并记录校验错误信息；

中断恢复模块，用于在 AI Agent 执行中断后，从本地存储中读取持久化的运行状态数据和步骤状态数据，向 AI Agent 提供当前执行进度和下一步骤的产物路径及校验要求，使 AI Agent 能够从中断点继续执行而不依赖对话上下文。

## 从属权利要求 14-20（系统细化）

14. 根据权利要求 13 所述的系统，其特征在于，所述门禁校验模块的步骤完成操作具有幂等性：对已处于已完成状态的步骤重复执行完成操作时，返回已完成提示，不修改已记录的完成时间，不重复推进当前步骤指针，不影响后续步骤的状态。

15. 根据权利要求 13 所述的系统，其特征在于，所述有效数据校验中，占位符的判定规则包括：空值、尖括号包围的模板文本、不区分大小写的待定标记和预定义的待补充标记；当表格所有数据行的关键列均被判定为占位符时，判定为校验失败。

16. 根据权利要求 13 所述的系统，其特征在于，所述状态管理模块在创建运行实例时生成的唯一运行标识包含时间戳和微秒级精度标记，同一任务多次创建运行实例时生成不同的运行标识，不覆盖历史运行记录。

17. 根据权利要求 13 所述的系统，其特征在于，还包括产物合并模块，用于按步骤序列顺序将所有处于已完成状态的步骤的产物文件内容合并输出为完整的测试交付文档。

18. 根据权利要求 13 所述的系统，其特征在于，还包括全局校验模块，用于检查目标产物类型对应的终点步骤是否已完成且所有必经步骤均无已阻塞状态，满足条件时输出目标已达成信号。

19. 根据权利要求 13 所述的系统，其特征在于，所述系统通过交互接口向 AI Agent 提供以下操作：
- 创建操作：创建工作流运行实例并返回运行标识和首个步骤信息；
- 状态查询操作：返回所有步骤的当前状态；
- 下一步查询操作：返回当前应执行步骤的产物路径和校验要求；
- 完成操作：对指定步骤执行门禁校验并更新状态；
- 全局校验操作：检查目标产物是否已达成；
- 合并输出操作：将已完成产物合并输出。

20. 根据权利要求 13 所述的系统，其特征在于，所述工作流配置数据定义的步骤序列为测试实施步骤序列，包括输入资料确认、测试范围确认、环境前置判断、测试工具选型、测试实施指南、测试执行记录、最终报告和测试工程反思共八个步骤。
