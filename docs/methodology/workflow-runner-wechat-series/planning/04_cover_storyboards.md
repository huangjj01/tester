# Workflow Runner 专题 6 篇封面脚本

## 使用说明

这份文档不是最终设计稿，而是逐篇封面的执行脚本。后续无论是我来出图，还是别的 agent 先做草图，都应该以这里的“标题、画面、构图、关键词、禁忌项”为准。

每篇都分 6 个部分：

1. 封面标题
2. 封面副标
3. 画面核心隐喻
4. 构图建议
5. 设计关键词
6. 禁忌项

## 第 1 篇

### 正文标题

为什么写了那么多 Agent 规范，结果还是一地鸡毛？

### 封面标题

Agent 规范  
为什么总失效

### 封面副标

文档写得越全，执行未必越稳

### 画面核心隐喻

画面上层是多份规则文档、流程卡片、skill 标签，排列得很整齐；下层却是一条已经偏航的流程轨道，几个关键节点闪着红色异常点。上层“很有秩序”，下层“已经失控”，形成明显反差。

### 构图建议

- 上 40% 放规则文档堆叠
- 下 60% 放偏航流程轨道
- 标题压在左中区域
- 右下角保留一个红色异常提示点，形成视觉钩子

### 设计关键词

- drift
- broken workflow
- documentation overload
- false control

### 禁忌项

- 不要画机器人脸
- 不要做成“很多纸张飞舞”的廉价科技风
- 不要让红色面积太大，否则像告警海报

## 第 2 篇

### 正文标题

文档会说话，Agent 不一定会照做：问题到底卡在哪

### 封面标题

规则写下了  
门禁却没落地

### 封面副标

失效的不是规则，是执行闭环

### 画面核心隐喻

左边是一列 Markdown 文档、checklist、workflow 路由图，右边是一条散开的执行流，中间有一道明显断层，像桥没有接上。断层附近漂浮着几个关键词：`state`、`checkpoint`、`blocked`。

### 构图建议

- 左右分栏
- 左边偏亮，右边偏暗
- 中间断层处用青色和红色形成张力
- 标题可以放在断层上方，形成“拦腰切断”的感觉

### 设计关键词

- gap
- execution gap
- disconnected layers
- broken bridge

### 禁忌项

- 不要堆太多术语文字
- 不要做成纯流程图封面，封面还是要有情绪张力

## 第 3 篇

### 正文标题

从文档约束到可执行门禁：我们为什么做 Workflow Runner

### 封面标题

Workflow Runner

### 封面副标

把文档要求，变成 Agent 绕不过去的门

### 画面核心隐喻

一条原本杂乱分叉的流程线，经过中央一道发光门禁后，被收束成一条稳定轨道。门禁主体可以是抽象几何结构，不要太像现实安检门，但要让人一眼理解“这里是检查口”。

### 构图建议

- 中央对称构图
- 主标题居中偏上
- 门禁主体放在视觉中心
- 流程线从画面外缘汇入中间再向下延伸

### 设计关键词

- gate
- checkpoint
- convergence
- controlled flow

### 禁忌项

- 不要用传统网页后台 UI 截图当封面
- 不要把画面做得过硬核，失去传播感

## 第 4 篇

### 正文标题

不是再造平台，而是加一道门：Workflow Runner 怎么工作

### 封面标题

8 步流程  
4 种 target

### 封面副标

Runner 的关键，不在界面，在状态推进

### 画面核心隐喻

像一张被高度提炼过的工程蓝图。8 个步骤以清晰的路径串联，部分节点收束到不同 target 分支，所有路径最终都要经过校验点。整体是“复杂但有秩序”的观感。

### 构图建议

- 使用 B 版方案
- 左到右或上到下均可，但要有明显主路径
- 节点不要写太多字，更多靠编号和色块区分
- 右上角加 `04 / 06`

### 设计关键词

- state transition
- workflow map
- target mode
- validation path

### 禁忌项

- 不要把 8 个步骤的完整中文名都塞上去
- 不要做成普通产品流程图截图

## 第 5 篇

### 正文标题

43 条用例、2 个失败、1 次复测：Runner 值不值得做

### 封面标题

43 条用例  
拷问 Runner

### 封面副标

2 个失败，1 次复测，才有资格谈可信

### 画面核心隐喻

大数字是主角。`43`、`2`、`1` 三组数字纵深排开，周围是测试矩阵、状态点、红绿变化轨迹。让人一眼就知道这篇讲的是“拿真实验证说话”。

### 构图建议

- 数字置于视觉中心
- `43` 最大，`2` 和 `1` 作为节奏点
- 用红点标失败、绿点标复测通过
- 背景可弱化加入 grid 和 checklist 纹理

### 设计关键词

- verification
- test matrix
- red to green
- evidence-driven

### 禁忌项

- 不要变成运营海报风
- 不要把数字做成夸张电商促销样式

## 第 6 篇

### 正文标题

真正有价值的，不是把 Agent 管死，而是让交付可追溯

### 封面标题

别把 Agent 管死

### 封面副标

真正重要的，是交付可验证、过程可追溯

### 画面核心隐喻

一套流程门禁向远处延展，但在几个关键节点保留了明显的人类判断标记。整体感觉像一张正在继续铺开的工程地图，说明这不是终局，而是有边界的持续建设。

### 构图建议

- 留白比前几篇更多
- 中景是一条延伸中的流程线
- 近景用 1~2 个高亮判断节点作为视觉锚点
- 标题放左下或左中，气质更沉稳

### 设计关键词

- boundary
- human-in-the-loop
- audit trail
- controlled evolution

### 禁忌项

- 不要做成鸡汤收官图
- 不要出现“未来城市”“宇宙空间站”这类跑题背景

## 系列统一小规则

### 期数标识

- 第 1 篇：`01 / 06`
- 第 2 篇：`02 / 06`
- 第 3 篇：`03 / 06`
- 第 4 篇：`04 / 06`
- 第 5 篇：`05 / 06`
- 第 6 篇：`06 / 06`

### 系列统一小标签

- `Agent Testing`
- `Workflow Runner Series`

### 封面统一裁切口径

- 先按公众号头图比例设计主画面
- 再兼容文章分享卡片裁切
- 重要文字和主体不要贴边，给平台裁切留安全区

## 最后判断

这 6 张封面真正要传达的，不是“AI 很酷”，而是：

**这是一套正在把 Agent 工程治理做实的东西。**
