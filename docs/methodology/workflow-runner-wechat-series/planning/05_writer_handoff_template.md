# Workflow Runner 专题写作协作模板

## 1. 这份模板的用途

这份模板给后续负责“真实落地文章正文”的 agent 使用。目标不是帮它写文章，而是约束它交付一种我可以直接接力做图片、做终稿排版的半成品。

换句话说，正文 agent 写完后，至少要让我一眼看到：

- 这篇到底想讲什么
- 每个观点依据哪份真实材料
- 哪些地方已经有证据，哪些地方还不能下结论
- 每张图该承担什么任务

## 2. 交付原则

正文 agent 必须遵守：

1. 只写仓库内已有证据支撑的事实。
2. 工程判断和事实要分开写。
3. 所有图片需求必须留 `插图位`。
4. 不允许写“后面补图时再看着办”这种模糊占位。
5. 如果缺证据，直接标 `待补`，不要脑补。

## 4. 插图位填写标准

### 图类型允许值

- `封面`
- `主逻辑图`
- `证据图`
- `对比图`
- `摘要卡片`

### 图目的写法

不要写“配个图更好看”，要写这张图解决什么问题。

好的写法：

- 让读者一眼看懂“文档约束”和“执行门禁”不是一回事
- 让读者快速记住 Runner 的 8 步结构
- 用真实测试结果建立方案可信度

不好的写法：

- 这里放一张图
- 这里后面补图
- 这里做个高级点的图

### 图依据写法

必须落到真实材料，至少写到文件级。

好的写法：

- `docs/methodology/agent-testing-methodology/test_agent_workflow_runner_design.md`
- `docs/methodology/agent-testing-methodology/test_agent_workflow_runner_execution_record_20260520_local.md`

不好的写法：

- 设计文档
- 测试记录
- 仓库资料

### 图重点写法

只写“读者应该一眼看到什么”，不要把整段正文贴进来。

例子：

- 一眼看到流程被门禁收束
- 一眼看到 43 / 2 / 1 三个数字
- 一眼看到 blocked 和 target achieved 的对比

## 5. 正文中的事实口径模板

为了避免后续文章写得太满，建议正文 agent 优先使用下面这些口径：

- “从当前仓库中的设计与验证材料看……”
- “现阶段已完成的是本地实现与本地验证……”
- “本文讨论范围聚焦测试实施 workflow……”
- “这一点在首轮执行记录和失败复测记录中都有对应证据……”
- “更大范围的推广效果，当前材料还不足以下结论……”

## 6. 给写作 agent 的最低交付要求

如果时间紧，至少也要交齐这 5 项：

1. 标题和唯一核心观点
2. 事实依据表
3. 完整正文结构
4. 至少 3 个有效 `插图位`
5. 边界与待补项

少于这 5 项，我这边做图时就容易返工。

## 7. 建议的协作顺序

最推荐的协作方式是：

1. 正文 agent 先按这份模板交一版第 1 篇
2. 我根据 `插图位` 和证据表补封面与正文图
3. 双方再同步微调标题和重点
4. 跑通后复制到第 3、5 篇

原因很简单：第 1 篇是痛点篇，最能验证这套写作-设计协作方式顺不顺。
