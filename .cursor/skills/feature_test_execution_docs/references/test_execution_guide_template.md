- 测试过程默认不得使用 `sudo` 破坏执行环境；除 `systemctl` 停启明确 unit 等真实特权边界外，不得默认使用 `sudo` 创建、删除、清理或改属主。

- 若普通运行用户无权写入目标目录，必须标记为 `阻塞：ownership 待修复`，不得用 `sudo` 绕过；一次性修复必须经人类工程师明确授权并限定目标路径。

- `当前能力判断` 和 `是否需要改造` 由 Agent 根据业务用例先判断，但结果必须由人类工程师确认。

- 需要新增或改造自动化用例时，用例草稿放在独立文件，且必须与落地形式的反解析结构同构。测试意图和断言说明只写入用例描述字段；实施指南只记录路径、审核状态、落地状态和对账结果。
- 能自动断言的，不只做人工观察；长稳脚本适合持续执行和跨周期状态类验证，自动化用例工具适合精确单 case 和固定回归。
- mock / 模拟器是公共工具能力，不属于测试环境；所有依赖外部特殊回报的 case 都必须先确认 mock 能力。
